## Repository Overview

GenApp is a general insurance application for IBM CICS Transaction Server for z/OS. It's a demonstration COBOL application designed to illustrate application modernization techniques, featuring a three-tier architecture (presentation, business logic, data management) that manages customer information and insurance policies.

## Build and Deployment Commands

### Installation and Customization
1. Edit `CUST1` in `userid.GENAPP.EXEC` data set with your environment values
2. Run: `EXEC 'userid.GENAPP.EXEC(CUST1)'` to customize JCL files (creates @-prefixed versions)

### Build Sequence (submit jobs in order)
1. `@ADEF121` - Create VSAM application files and populate with data
2. `@ASMMAP` - Build BMS maps for 3270 interface (returns RC=4, which is normal)
3. `@CDEF121` - Add resource definitions to CSD (group list: GENALIST)
4. `@COBOL` - Compile COBOL programs to `userid.GENAPP.LOAD` library
5. `@DB2CRE` - Create Db2 database, tables, indexes, and populate with data
6. `@DB2BIND` - Bind application to Db2 objects

### Optional Coupling Facility Setup
- `@SAMPNCS` - Create named counter server (pool: GENA, structure: DFHNCLS_GENA)
- `@SAMPTSQ` - Create temporary storage queue server (pool: GENA, structure: DFHXQLS_GENA)

### Cleanup
- `@DB2DEL` - Delete Db2 database (use when rebuilding environment)

### Testing Commands
- `LGSE` - Initialize control tables, clear shared temporary storage queue and named counter
- `SSC1` - Customer details menu (inquire on customers 1-10, add new customers)
- `SSP1` - Motor policy options menu
- `SSP2` - Endowment policy options menu
- `SSP3` - House policy options menu
- `SSP4` - Commercial property options menu

## Architecture

### Three-Tier Design
The application uses EXEC CICS LINK commands to call between layers:

1. **Presentation Layer** (`lgtestXX.cbl`)
   - Handles 3270 BMS screen interaction
   - Links to business logic layer
   - Programs: `lgtestc1`, `lgtestp1`, `lgtestp2`, `lgtestp3`, `lgtestp4`

2. **Business Logic Layer** (`lgXXus01.cbl`, `lgXXpol01.cbl`)
   - Implements insurance business rules
   - Links to data management layer
   - Customer operations: `lgacus01`, `lgicus01`, `lgucus01`
   - Policy operations: `lgapol01`, `lgipol01`, `lgupol01`, `lgdpol01`

3. **Data Management Layer** (`lgXXdb01.cbl`, `lgXXvs01.cbl`)
   - Database access: `lgXXdb01` programs interact with Db2
   - File access: `lgXXvs01` programs interact with VSAM
   - Uses two-phase commit for Db2 and VSAM consistency

### Program Naming Convention
- Format: `lgX[action][type][number]`
  - `X` = functional area (a=add, i=inquire, u=update, d=delete)
  - `action` = operation (cus=customer, pol=policy)
  - `type` = component type (db=database, vs=VSAM)
  - `number` = sequence number (usually 01)
- Example: `lgacdb01` = "Logic for adding customer to database, version 01"

### Data Storage
- **VSAM Files**:
  - `KSDSCUST` - Customer records (key: first 10 chars = customer ID)
  - `KSDSPOLY` - Policy records (key: first 21 chars = policy type + customer ID + policy number)

- **Db2 Tables**:
  - Customer table (with customer number)
  - Policy table (with customer number, policy number, policy type)
  - Specialized policy tables: commercial, endowment, house, motor

- **Policy Type Indicators** (first character in KSDSPOLY key):
  - `C` - Commercial property insurance
  - `E` - Endowment insurance
  - `H` - House insurance
  - `M` - Motor insurance

### Key Architecture Patterns
- Communication between layers uses COMMAREA structures (defined in copybooks)
- Customer numbers generated either from named counter server (EXEC CICS GET COUNTER) or Db2
- Policy numbers generated by Db2 INSERT command
- Two-phase commit ensures Db2 and VSAM data consistency
- Optional shared temporary storage queues: GENACNTL (control data), GENAERRS (error logging)

## CICS Configuration Requirements

### System Initialization Parameters
```
GRPLIST=(DFHLIST,GENALIST)
DB2CONN=YES
NCPLDFT=GENA
```

### Required Concatenations
- Add `userid.GENAPP.LOAD` to DFHRPL
- Include Db2 libraries in STEPLIB and DFHRPL

## Key File Locations

- `/base/src/` - COBOL programs (.cbl) and copybooks (.cpy)
- `/base/cntl/` - JCL jobs for building and configuring
- `/base/data/` - Sample data files
- `/base/exec/` - REXX customization scripts
- `/base/wsim/` - Workload Simulator scripts
- `/base/event-bindings/` - Event bindings
- `ssmap.bms` - BMS map for 3270 screen layouts

## Important Copybooks
- `lgcmarea.cpy` - COMMAREA structures for data passing
- `lgpolicy.cpy` - Policy data structures
- `pollook.cpy`, `polloo2.cpy` - Policy lookup structures

## Prerequisites
- IBM CICS Transaction Server for z/OS V4.1 or later
- IBM Db2
- COBOL compiler
- Optional: z/OS coupling facility for named counter server and shared temporary storage
