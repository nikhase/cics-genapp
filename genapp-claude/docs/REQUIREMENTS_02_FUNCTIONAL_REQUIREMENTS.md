## 🏢 Level 1: Business Capabilities

### Capability 1: Customer Management

**Description**: Ability to manage insurance customers (create, read, update, delete, search)

**Business Value**: Central hub for all customer information

**Features**:
- Create new customer
- View customer details
- Update customer information
- Delete customer (archive)
- Search customers by name, email, location
- List all customers with pagination

**Responsible Service**: CustomerService + CustomerController

---

### Capability 2: Policy Management

**Description**: Ability to manage 4 types of insurance policies with type-specific details

**Business Value**: Core business capability - manage all insurance products

**Policy Types**:
1. **Motor Policy** - Vehicle insurance
2. **House Policy** - Home/property insurance
3. **Endowment Policy** - Investment/life insurance
4. **Commercial Policy** - Business/commercial insurance

**Features**:
- Create policy of specific type
- View policy details (type-specific)
- Update policy information
- Cancel/terminate policy
- Search policies by customer, policy type, policy number
- List customer's policies

**Responsible Service**: PolicyService + PolicyController

---

### Capability 3: Search & Filtering

**Description**: Advanced search capabilities across customers and policies

**Business Value**: Faster access to information

**Features**:
- Search customers by full name (first + last name)
- Filter customers by state/location
- Search policies by policy number
- Filter policies by customer ID
- Filter policies by policy type
- Filter policies by status (active, terminated, expired)

**Responsible Service**: Repository query methods + API endpoints

---

### Capability 4: Data Persistence

**Description**: Reliable storage of all customer and policy data

**Business Value**: Single source of truth, data consistency

**Features**:
- PostgreSQL database with proper schema
- Automatic timestamps (created_at, updated_at)
- Data validation at database level (constraints)
- Proper indexing for performance
- Transaction support (ACID guarantees)

**Responsible Service**: Database layer + JPA

---

### Capability 5: API Documentation

**Description**: Interactive API documentation for developers

**Business Value**: Easier integration, reduced support requests

**Features**:
- Swagger UI for interactive testing
- OpenAPI 3.0 specification
- Request/response examples
- Parameter documentation
- Error code documentation

**Responsible Service**: Swagger/OpenAPI configuration

## ✅ Level 3: Acceptance Criteria (Given/When/Then)

### AC1: Create New Customer

**Given** a customer service representative is logged in
**And** they navigate to "Create Customer" form
**When** they enter valid customer information:
  - First Name: "John"
  - Last Name: "Doe"
  - Email: "john@example.com"
  - Phone: "(555) 123-4567"
  - Address: "123 Main St"
  - City: "New York"
  - State: "NY"
  - Zip Code: "10001"
**Then**:
  - Customer is created in database
  - System returns 201 Created
  - Customer ID is auto-generated (e.g., 1, 2, 3...)
  - Confirmation message shows
  - Agent can view newly created customer

---

### AC2: Validate Customer Email Uniqueness

**Given** a customer with email "john@example.com" already exists
**When** agent tries to create another customer with same email
**Then**:
  - System shows error: "Customer with email 'john@example.com' already exists"
  - HTTP 409 Conflict returned
  - No duplicate created in database

---

### AC3: Validate Required Fields

**Given** agent is creating a customer
**When** they skip required field (e.g., leave First Name empty)
**Then**:
  - System shows validation error: "First name is required"
  - HTTP 400 Bad Request returned
  - Customer not created

---

### AC4: Validate Field Lengths

**Given** agent is creating a customer
**When** they enter phone number with invalid format (e.g., "abc123")
**Then**:
  - System shows error: "Invalid phone number format"
  - HTTP 400 Bad Request returned
  - Customer not created

---

### AC5: View Customer Details

**Given** customer with ID 1 exists in database
**When** agent requests GET /api/customers/1
**Then**:
  - System returns HTTP 200 OK
  - Response includes all customer fields:
    - customerId, firstName, lastName, email, phone, address, city, state, zipCode
  - Response is JSON format
  - Response size < 2KB

---

### AC6: Search Customers by Name

**Given** multiple customers exist (John Doe, Jane Smith, John Brown)
**When** agent searches with pattern "john"
**Then**:
  - System returns all customers with "john" in name (case-insensitive)
  - Returns: John Doe, John Brown
  - Returns HTTP 200 OK
  - Results ordered by last name, then first name

---

### AC14: List All Customers with Pagination

**Given** 100 customers exist in database
**When** agent calls GET /api/customers?page=1&size=20
**Then**:
  - System returns HTTP 200 OK
  - Returns 20 customers on first page
  - Response includes pagination info (total, page, size)
  - Second page accessible via ?page=2

---

### AC15: API Response Time Target

**Given** any API endpoint is called
**When** request is processed normally
**Then**:
  - Response time < 50ms (90th percentile)
  - Database query time < 10ms
  - No timeout errors

---

### AC16: Error Handling

**Given** agent calls GET /api/customers/999 (non-existent)
**When** request is processed
**Then**:
  - System returns HTTP 404 Not Found
  - JSON response includes:
    - status: 404
    - message: "Customer not found with ID: 999"
    - timestamp: ISO 8601 format
  - No stack trace in response (security)

---

### AC17: Data Validation - Email Format

**Given** agent creates customer
**When** they enter email "invalid-email" (not valid format)
**Then**:
  - System shows validation error: "Invalid email format"
  - HTTP 400 Bad Request returned
  - Customer not created

---

### AC18: Data Validation - State Code

**Given** agent creates customer
**When** they enter state "california" (should be 2-letter code)
**Then**:
  - System shows validation error: "State must be 2 characters"
  - HTTP 400 Bad Request returned

---

### AC19: Data Validation - ZIP Code

**Given** agent creates customer
**When** they enter ZIP code "abcde" (invalid format)
**Then**:
  - System accepts empty/null ZIP (optional)
  - System accepts valid formats: "12345" or "12345-6789"
  - System rejects invalid formats with error message

---

### AC20: Field Normalization

**Given** agent creates customer with:
  - First Name: "  JOHN  " (extra spaces, uppercase)
  - Email: "John@EXAMPLE.COM" (mixed case)
  - State: "ca" (lowercase)
**When** customer is created
**Then**:
  - First Name trimmed to "JOHN" (case preserved)
  - Email normalized to "john@example.com" (lowercase)
  - State normalized to "CA" (uppercase)
