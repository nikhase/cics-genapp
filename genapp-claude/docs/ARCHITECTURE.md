## 🔄 COBOL → Java Mappings

### 1. Entity & Data Model

| COBOL | Purpose | Java | Benefits |
|-------|---------|------|----------|
| `lgcmarea.cpy` COMMAREA (32.5KB) | Inter-program data passing | `CustomerDTO` Record (2-3KB as JSON) | Type-safe, smaller, serializable |
| `COBOL PICTURE` clauses | Field definitions | `@Entity` with validation annotations | Declarative, self-documenting |
| VSAM KSDSCUST file (indexed sequential) | Primary customer storage | PostgreSQL `customers` table | ACID, complex queries, indexing |
| Db2 CUSTOMER table | Backup/dual storage | PostgreSQL (single source) | Consistency, no dual-write |

### 2. Business Logic Flow

#### Old COBOL Pattern
```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. LGACUS01.

LINKAGE SECTION.
01 LS-CUST-REC.
   05 LS-CUST-ID        PIC 9(10) VALUE ZERO.
   05 LS-FIRST-NAME     PIC X(30).
   ...

PROCEDURE DIVISION USING LS-CUST-REC.

   PERFORM VALIDATE-INPUT.
   PERFORM CHECK-DUPLICATE-EMAIL.
   PERFORM INSERT-TO-DB2.
   PERFORM INSERT-TO-VSAM.
   PERFORM TWO-PHASE-COMMIT.

   EXEC CICS RETURN
   END-EXEC.
```

#### New Java Pattern
```java
@Service
@Transactional  // Automatic transaction management
public class CustomerService {

    public CustomerDTO createCustomer(CustomerDTO dto) {
        // Input validation (declarative via @Valid)
        if (customerRepository.existsByEmail(dto.email())) {
            throw new IllegalArgumentException("Email exists");
        }

        // Map to entity
        Customer customer = new Customer();
        customer.setFirstName(dto.firstName());
        // ...

        // Save to database (one write, automatic indexing)
        return convertToDTO(customerRepository.save(customer));
        // @Transactional automatically commits or rolls back
    }
}
```

**Key Improvements:**
- `@Transactional` replaces manual two-phase commit
- No dual-write (Db2 + VSAM) issues
- Single source of truth
- Automatic rollback on exception

### 3. Data Access Patterns

| COBOL | Java | Equivalent |
|-------|------|-----------|
| `EXEC CICS READ FILE('KSDSCUST')` | `customerRepository.findByEmail(email)` | `Optional<Customer>` |
| `EXEC CICS WRITE FILE('KSDSCUST')` | `customerRepository.save(customer)` | INSERT or UPDATE |
| Loop through file reading | `customerRepository.findAll()` | Automatic pagination/streaming |
| Manual matching loop | `customerRepository.findByFirstName(name)` | Custom query |

### 4. Error Handling

#### Old COBOL Pattern
```cobol
EXEC CICS READ FILE('KSDSCUST')
    INTO WS-CUST-REC
    RESP WS-RESP
    RESP2 WS-RESP2
END-EXEC.

EVALUATE WS-RESP
    WHEN DFHRESP(NORMAL)
        MOVE 0 TO WS-STATUS-CODE
    WHEN DFHRESP(NOTFND)
        MOVE 404 TO WS-STATUS-CODE
    WHEN DFHRESP(ILLOGIC)
        MOVE 500 TO WS-STATUS-CODE
END-EVALUATE.
```

#### New Java Pattern
```java
@ExceptionHandler(IllegalArgumentException.class)
@ResponseStatus(HttpStatus.NOT_FOUND)
public ResponseEntity<ErrorResponse> handleNotFoundException(
        IllegalArgumentException ex) {
    return ResponseEntity.status(HttpStatus.NOT_FOUND)
        .body(new ErrorResponse(404, ex.getMessage(), LocalDateTime.now()));
}
```

**Benefits:**
- Exceptions propagate automatically
- `@ControllerAdvice` handles all controllers centrally
- Proper HTTP status codes
- JSON error responses
- No manual error code checking on every call

## 🏗️ Layered Architecture Pattern

### Clean Architecture Principles

```
┌─────────────────────────────────────────┐
│         REST API Layer                  │
│  @RestController → JSON/HTTP            │
├─────────────────────────────────────────┤
│    Business Logic Layer                 │
│  @Service → Validation & Rules          │
├─────────────────────────────────────────┤
│    Data Access Layer                    │
│  @Repository → JPA / SQL                │
├─────────────────────────────────────────┤
│      Database                           │
│  PostgreSQL → Persistence               │
└─────────────────────────────────────────┘

Dependencies: REST → Service → Repository → DB
(Unidirectional, loose coupling)
```

### Layer Responsibilities

#### 1. **REST Controller Layer** (`CustomerController.java`)
- **Responsibility**: Handle HTTP requests/responses
- **Annotations**: `@RestController`, `@RequestMapping`, `@GetMapping`, etc.
- **Input**: HTTP request with JSON body
- **Output**: HTTP response with JSON body + status code
- **Validation**: `@Valid` triggers validation
- **No business logic**: Just routing & serialization

**Example Endpoint:**
```java
@PostMapping
@ResponseStatus(HttpStatus.CREATED)
public ResponseEntity<CustomerDTO> createCustomer(
        @Valid @RequestBody CustomerDTO customerDTO) {
    log.info("Creating customer: {}", customerDTO.firstName());
    CustomerDTO created = customerService.createCustomer(customerDTO);
    return ResponseEntity
        .status(HttpStatus.CREATED)
        .header("Location", "/api/customers/" + created.customerId())
        .body(created);
}
```

#### 2. **Service Layer** (`CustomerService.java`)
- **Responsibility**: Business logic & validation
- **Annotations**: `@Service`, `@Transactional`
- **Input**: DTO from controller
- **Output**: DTO to controller
- **Transactions**: `@Transactional` manages auto-commit/rollback
- **No HTTP knowledge**: Pure business logic

**Example Service Method:**
```java
@Transactional
public CustomerDTO createCustomer(CustomerDTO dto) {
    // Check business rules
    if (customerRepository.existsByEmail(dto.email())) {
        throw new IllegalArgumentException("Email already exists");
    }

    // Convert DTO → Entity
    Customer customer = mapToEntity(dto);

    // Persist & return
    Customer saved = customerRepository.save(customer);
    return mapToDTO(saved);
}
```

#### 3. **Repository Layer** (`CustomerRepository.java`)
- **Responsibility**: Data access abstraction
- **Annotations**: `@Repository` (optional, Spring Data handles it)
- **Input**: Entity objects or primitive values
- **Output**: Entity objects or collections
- **Database interaction**: Automatic SQL generation by Hibernate
- **No business logic**: Just CRUD & queries

**Example Repository:**
```java
public interface CustomerRepository extends JpaRepository<Customer, Long> {
    Optional<Customer> findByEmail(String email);
    List<Customer> findByFirstNameIgnoreCase(String firstName);
    boolean existsByEmail(String email);

    @Query("SELECT c FROM Customer c WHERE ...")
    List<Customer> searchByFullName(@Param("pattern") String pattern);
}
```

#### 4. **Entity Layer** (`Customer.java`)
- **Responsibility**: Database table mapping & validation
- **Annotations**: `@Entity`, `@Table`, `@Column`, `@Id`
- **Validation**: `@NotBlank`, `@Email`, `@Size`, etc.
- **Lombok**: `@Data` auto-generates getters/setters/equals/hashCode
- **Lifecycle**: `@PrePersist`, `@PreUpdate` for timestamps

**Example Entity:**
```java
@Entity
@Table(name = "customers")
@Data
public class Customer {
    @Id
    @GeneratedValue(strategy = GenerationType.SEQUENCE)
    private Long customerId;

    @NotBlank(message = "First name is required")
    @Size(min = 1, max = 50)
    private String firstName;

    @Email(message = "Invalid email format")
    @Column(unique = true)
    private String email;

    @PrePersist
    protected void onCreate() {
        createdAt = LocalDateTime.now();
    }
}
```

#### 5. **DTO Layer** (`CustomerDTO.java`)
- **Responsibility**: Data transfer between layers
- **Immutable**: Java 21 Record (sealed, no setters)
- **Validation**: Annotations on record fields
- **Compact Constructor**: Normalize data during creation
- **Smaller payload**: Only fields needed by API client

**Example DTO:**
```java
public record CustomerDTO(
    @Null(message = "ID must be null for creates")
    Long customerId,

    @NotBlank(message = "First name required")
    @Size(min = 1, max = 50)
    String firstName,

    @Email(message = "Invalid email")
    String email,

    // ... other fields
) {
    // Compact constructor normalizes input
    public CustomerDTO {
        firstName = firstName != null ? firstName.trim() : null;
        email = email != null ? email.toLowerCase() : null;
    }
}
```

    // 1. Deserializes JSON → CustomerDTO

    // 3. Calls compact constructor (normalize data)

#### 3️⃣ CustomerService.createCustomer()
```java
@Transactional  // Spring starts transaction
public CustomerDTO createCustomer(CustomerDTO dto) {
    // Business logic layer

    // 1. Check for duplicate email
    if (customerRepository.existsByEmail(dto.email())) {
        throw new IllegalArgumentException("Email already exists");
        // Exception caught by GlobalExceptionHandler → 409 Conflict
    }

    // 2. Map DTO → Entity
    Customer customer = new Customer();
    customer.setFirstName(dto.firstName());
    customer.setEmail(dto.email());
    // ... set other fields

    // 3. Persist to database
    Customer saved = customerRepository.save(customer);
    // Hibernate generates: INSERT INTO customers (...) VALUES (...)

    // 4. @Transactional automatically commits here

    // 5. Return as DTO
    return convertToDTO(saved);
}
```

## 🔒 Exception Handling

### GlobalExceptionHandler Pattern

```java
@ControllerAdvice
@Slf4j
public class GlobalExceptionHandler {

    // Handle validation errors (400 Bad Request)
    @ExceptionHandler(MethodArgumentNotValidException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public ResponseEntity<ErrorResponse> handleValidationException(...) {
        // Return 400 with field-level error messages
    }

    // Handle not found (404 Not Found)
    @ExceptionHandler(IllegalArgumentException.class)
    @ResponseStatus(HttpStatus.NOT_FOUND)
    public ResponseEntity<ErrorResponse> handleNotFoundException(...) {
        // Return 404 with error message
    }

    // Handle conflicts (409 Conflict)
    @ExceptionHandler(IllegalStateException.class)
    @ResponseStatus(HttpStatus.CONFLICT)
    public ResponseEntity<ErrorResponse> handleConflictException(...) {
        // Return 409 for duplicate email, etc.
    }

    // Handle all other errors (500 Internal Server Error)
    @ExceptionHandler(Exception.class)
    @ResponseStatus(HttpStatus.INTERNAL_SERVER_ERROR)
    public ResponseEntity<ErrorResponse> handleGeneralException(...) {
        // Return 500 with generic error message
    }
}
```

**Benefits:**
- ✅ Centralized error handling
- ✅ Consistent error response format
- ✅ Proper HTTP status codes
- ✅ No try-catch in controllers
- ✅ Automatic logging
